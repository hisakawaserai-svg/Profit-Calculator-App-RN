# UI インベントリ — 現状の全画面・全要素の棚卸し

UI 設計を見直すための入力資料。**現在コードに存在する要素の事実のみ**を列挙する。
良し悪しの評価・改善提案は書かない（末尾の付録 A は種別フィルタの補足と Step 5 の予定、
付録 B は「これから追加が検討されている要素」の列挙）。

- 対象: React Native 版（`app-rn/`）。時点は Step 4（種別フィルタ）完了時。
- ファイルパスは `app-rn/` からの相対（`docs/SPEC-V2.md` と同じ基準）。
- 元の SwiftUI 版（リポジトリ直下の `*.swift`）は移植元であり、本書の対象外。
- 「条件」列が空の要素は常時表示。

### 用語

- **種別**: レコードの属性 `kind`。`used` = 不用品 / `sourced` = 仕入品（SPEC-V2 §1.1）。
- **種別語 / 中立語**: 金額ラベルの使い分け。レコード 1 件は種別語（不用品＝「純利益」/ 仕入品＝「利益」）、
  2 件以上の合計は中立語「収支」（SPEC-V2 §5.3）。文字列は `src/logic/labels.ts` に集約されている。
- **種別フィルタ**: 表示対象を種別で絞る「すべて / 不用品 / 仕入品」の 3 択（SPEC-V2 §4.2）。
  選択値と表示名は `src/logic/kindFilter.ts` に集約されている（`'all'` を repository へ渡す直前に
  「条件なし」へ変換する）。月別一覧・月別詳細・データタブの 3 画面が持ち、状態は画面ごとに独立。

## 1. 計算タブ

| 結果（表示側） | 区切り線 | 罫線 | 売上と費用の区切り | 同上 |

## 2. 出品中タブ / 実績タブ（月別一覧）

**ファイル**: `src/screens/MonthlyRecordListScreen.tsx`
**ルート**: `/listings`（`isSoldMode = false`）、`/sold`（`isSoldMode = true`）
**ヘッダタイトル**: 出品中タブ = 「出品中」固定 / 実績タブ = 「全期間の収支」、月選択時は「YYYY年M月の収支」

| オーバーレイ | 記録フォーム | `RecordFormSheet` | ＋ボタンで開くシート。保存時に一覧を再取得 | 開いている間のみ |

## 付録 A. 種別フィルタ（Step 4・実装済み）と Step 5 の予定

種別フィルタは実装済みで、要素そのものは §2.1 / §3.1 / §6.1 の各表に載せてある。
ここには表に収まらない仕様（適用範囲と、決定により**作らなかった**要素）だけを残す。
根拠は `docs/SPEC-V2.md` §1.3 / §4.1 / §4.2 / §4.3 / §4.4 / §5.4 / §7-10。

| 画面 | 置き場所 | 選択肢 |
|---|---|---|
| 出品中 / 実績タブ | 既存のソートメニュー（`OptionSheet`）に見出し「種別」のセクションを追加 | すべて / 不用品 / 仕入品 |
| 月別詳細 | 同上 | 同上 |
| データタブ | 表示単位・指標の切替と同じ列（`OptionSheet` を使っていないため） | 同上 |

- 適用範囲はリスト本体だけでなく**下部累計にも及ぶ**（検索文字列とは扱いが異なる）。
  データタブではサマリー・グラフ・内訳のすべてに効く。
- 状態は画面ごとに独立で、他画面・再起動には引き継がれない（検索・ソート・月フィルタと同じ扱い）。
  月別一覧では「フィルタをリセット」ボタンで「すべて」に戻る。
- 月次カード・データタブのサマリーを種別ごとの 2 系統に増やすことは**行っていない**（§4.1 / §4.3）。
  種別ごとの合計はこのフィルタで得る。
- 一覧・行への種別バッジは**置いていない**（§5.4）。種別が読めるのはレコード詳細の「種別」行のみ。
- 種別で色分けした積み上げグラフは**行っていない**（§4.4）。

Step 5（未実装）: ヘルプタブに「記録の種別について」セクションと、経費の範囲に関する注記
（本アプリの純利益は販売サイト表示の「手取り」より少なくなり得る）を追加する。
要素としてはヘルプ項目の追加のみで、新しい部品は増えない。
