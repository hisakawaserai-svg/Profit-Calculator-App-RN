# UI 全面改訂 仕様 — UI-SPEC

出典: Claude Design プロジェクト「フリマアプリUI設計の見直し」の `UI設計案.dc.html`
（<https://claude.ai/design/p/00205ddb-1a3a-4279-abfd-3a7ab68d3597>）。
設計案は 0〜9 の 10 ターンからなり、**ターン 9 で採用案が確定**している。

本書はその確定案（`3a` `8a` `3c` `3d` `7b` `5b`）を実装用に文章化したもの。
デザイン上の ID（`3a` など）は設計案側の option ID をそのまま引用する。

## 0. 位置づけと優先順位

- 本書は **UI の構成**（画面・配置・遷移）を定める。
- **表示ラベルと種別（不用品 / 仕入品）の扱いは SPEC-V2 §5.3 / §5.4 の決定が優先する。**
  設計案の描画にラベル差分がある箇所は本書 §6 に列挙し、**実装しない**。
- 計算式・DB スキーマ・電卓は現状維持（SPEC.md §2、`src/logic/profit.ts`、`src/db/**`、
  `src/components/MiniCalculator.tsx`）。設計案でも「変更なし」と明記されている。
- **本書の採用は SPEC.md の一部を無効化する**（5 タブ構成・月別詳細画面・データタブの
  指標/単位切替）。該当箇所は §6 に矛盾として挙げてあり、実装前に SPEC.md の改訂が要る。

## 1. 採用案の画面構成

### 1.1 計算タブ（案 `3a`）— `app/(tabs)/index.tsx`

**ねらい**: 結果を常に画面上部に置き、逆算を「おまけ」から対等な 2 択に格上げする。

**構成（上から）**

| # | 要素 | 内容 |
|---|---|---|
| 1 | ヘッダ | タイトル「利益計算」。右に「？」（使いかた）。→ 「設定」ボタンは §6-7 参照 |
| 2 | 固定バー（スクロール時のみ） | スクロール量 40px 超で上端にスライドイン。左に結果ラベル、右に結果額（30px 太字）。2 段目に「売上 ¥… ／ 経費 ¥…」と「内訳 ▼」。内訳を開くと送料・梱包・その他・販売手数料の 3 行 |
| 3 | 結果カード | 先頭に 2 択セグメント（利益計算 / 逆算）。→ セグメント名は §6-4 参照 |
| 3a | ├ 利益側 | 中央に結果ラベル（14〜15px）と結果額（46px 太字・正=緑/負=赤）。右上に「クリア」。下に「内訳 ▼」→ 売上総額 / 送料 / 梱包・その他 / 販売手数料（オレンジ） |
| 3b | └ 逆算側 | 「目標の純利益 / 目標利益」入力行（グレー地・右寄せ 22px）。下に「この値段で出せばよい」＋必要販売価格（46px 太字・青）＋「送料・手数料 N% を差し引いた後の金額です」 |
| 4 | 種別セレクタ | 「不用品 / 仕入品」の 2 択セグメント。結果カードの**下**に置く（→ §5-1） |
| 5 | 入力カード | 行型の数値欄（行高 60px）。販売価格 / 仕入価格（仕入品のみ）/ 送料 / 手数料 N%（− ＋ ステッパー）。各金額行の右端に電卓ボタン |
| 6 | 折りたたみ | 「梱包材・その他を入力 ▼」→ 開くと梱包材・その他の 2 行 |
| 7 | 下端固定ボタン | 「この内容で記録する」（青・高さ 54px）。半透明地＋上境界線でリストから浮かせる |

**挙動**

- 逆算モード中は販売価格欄をグレーアウト（背景 `rgba(120,120,128,.12)`・文字 60% 不透明）して無効化する。
- 固定バーは逆算モードでは見出しが「必要な販売価格」、売上側が「必要な売上」に変わり、色が青になる。
- 内訳の開閉状態は結果カードと固定バーで独立（設計案では別 state）。

### 1.2 記録タブ（案 `8a`）— `app/(tabs)/records/index.tsx`（新規）

**ねらい**: 「出品中」「実績」の 2 タブと月別詳細画面を 1 画面に統合し、上部の固定段を 3 段に収める
（ヘッダ + 月バー + 合計行）。一覧から詳細へ 1 タップ。

**構成（上から）**

| # | 要素 | 内容 |
|---|---|---|
| 1 | ヘッダ | タイトル「記録」。右に ⌕（検索）・⇅（並び替え）・？ の 3 ボタン |
| 2 | 月バー | `◀　2026年8月 ▾　▶`。中央タップで期間シート。**全期間を選んでいる間は両矢印を無効化**（`rgba(60,60,67,.25)`）。最新月では ▶、最古月では ◀ を無効化 |
| 3 | 合計行（固定） | 左に集計 2 値、右端に**状態チップ**と**種別フィルタチップ**の 2 つ |
| 4 | 件数 | リスト上に「N 件」（13px・グレー） |
| 5 | リスト | カード内に行を積む。行高は 2 段（商品名＋金額 / メタ行） |
| 6 | 空表示 | 見出し＋本文＋（絞り込み中のみ）「絞り込みを解除」リンク |
| 7 | 追加ボタン | 画面左下・タブバーの上（`left:20px; bottom:96px`）。青の丸角ボタン「＋ 記録」 |

**合計行の出し分け**

| 状態 | 左の値 A | 左の値 B | 左の値 C |
|---|---|---|---|
| 売れた記録 | 「この月の収支」/「全期間の収支」（緑） | 「経費」（赤） | — |
| 出品中 | 「出品中」= N 点（オレンジ） | 「出品価格の合計」（青）→ §6-5 | 「いちばん長い」= N 日 ※ `8a` では非表示、`8c` のみ |

**チップ**

- **状態チップ**（青地 `rgba(0,122,255,.12)`・青文字）: 「売れた記録 ▾」⇄「出品中 ▾」をタップでトグル。
- **種別フィルタチップ**（グレー地・黒文字）: 「すべて → 不用品 → 仕入品 → すべて」を巡回。

**行の出し分け**

| 状態 | 主金額（右上） | メタ行（右） |
|---|---|---|
| 売れた記録 | 純利益額（正=緑 / 負=赤） | 「経費 ¥…」 |
| 出品中 | **出品価格**（黒） | 「売れたら ¥…・N 日経過」。**送料が未入力なら「売れたら 約¥…（送料未定）」** と概算であることを明示 |

メタ行の左は「{種別}　{M/D 販売 or M/D 出品}」→ 種別の常時表示は §6-1 参照。

**期間シート**（月バー中央タップ）

- 見出し「表示する期間」。「全期間 / 2026年8月 / 2026年7月 / …」を縦に並べ、選択中に ✓ と青文字。

**空表示の文言**

| 状況 | 見出し | 本文 | 追加リンク |
|---|---|---|---|
| 絞り込みなし | この期間の記録はありません | 左下の ＋ を押すと記録できます | なし |
| 種別で絞り込み中 | 条件に合う記録がありません | 「{種別}」で絞り込んでいます。ほかの月にはあるかもしれません | 絞り込みを解除 |

**並び替えシート（⇅）**: 先頭に「絞り込みをすべて解除」を置く（設計案 `2e`）。頻度が低いので画面には出さない。

### 1.3 記録フォーム（案 `3c`）— `src/screens/RecordFormSheet.tsx`

**ねらい**: 伝票（レシート）型。金額を 1 枚のカードに縦に積み、下の行ほど結果に近づける。

**構成（上から）**

| # | 要素 | 内容 |
|---|---|---|
| 1 | シートハンドル | 幅 40px のグラバー |
| 2 | シートヘッダ | 「キャンセル」／「新しい記録」／「保存」（太字・青） |
| 3 | 伝票カード見出し行 | 左に状態ドット（緑=売れた / 出品中は別色）＋「売れた記録」、右に切替リンク「出品中にする」（設計案 `4b`） |
| 4 | 伝票カード本体 | 商品名（22px・下線は青 1.5px のインライン入力）→ その下に「商品名（必須）」のキャプション |
| 5 | ├ 販売価格 | 右寄せ 24px 太字。下に区切り線 |
| 6 | ├ − 送料 | 赤 20px |
| 7 | ├ − 手数料 N% | オレンジ 20px |
| 8 | ├ ＋ 梱包材・その他 | 青リンク。未入力時は右に「未入力」（40% グレー） |
| 9 | └ 結果行 | 太い区切り線（1.5px）の下に「純利益 / 利益」＋結果額（30px 太字・緑） |
| 10 | 日付カード | 販売日（「今日（2026/08/09）」青）/ 出品日 / 種別セレクタ → §6-6 参照 |

- 状態は見出し行のリンクで切り替える。上端に 2 択ボタンは置かない（金額の流れの前に無関係な操作が挟まるため。設計案ターン 4 の結論）。
- 販売日は出品中では非表示（SPEC.md §3.2 のまま）。
- 必須は商品名のみ（SPEC.md §5.2 のまま）。

### 1.5 データタブ（案 `7b`）— `app/(tabs)/data.tsx`

**ねらい**: 切替を減らし、記録タブと同じ月バー＋固定合計行に揃える。グラフは収支のみ。

**構成（上から）**

| # | 要素 | 内容 |
|---|---|---|
| 1 | ヘッダ | タイトル「データ」。右に「？」 |
| 2 | 月バー | 記録タブと同一（`◀ 2026年8月 ▾ ▶`） |
| 3 | 合計行（固定） | 「売上」（青）/「収支」（緑）/「経費」（赤）の 3 値＋右端に種別フィルタチップ |
| 4 | グラフカード | 見出し「収支の推移」＋右に刻みの表示（「日ごと」/「月ごと」）。棒グラフ。選択中の棒のみ濃色（`#34C759`）、他は 30% 不透明 |
| 5 | 選択日の一覧 | 「8月9日の記録　N件」＋右に「選択を解除」。下に記録行のカード |
| 6 | 注記 | 「全期間を選ぶと刻みが『月ごと』に変わり、見出しも『全期間の収支』になります。」 |

**廃止する切替（設計案ターン 6 の決定）**

| 廃止するもの | 代替 |
|---|---|
| 「今年」チップ | 全期間と期間指定で代用 |
| 指標切替（売上金額 / 収支） | 合計行に売上・収支・経費の 3 値を常時表示。※推移は見られなくなる（→ §5-4） |
| 表示単位切替（明細 / 日別 / 月別 / 年別） | **期間から自動決定: 62 日以下 = 日ごと、それ以上 = 月ごと**。刻みはグラフ左上に文字で出す |
| 「明細」（1 件ずつの折れ線） | 棒タップで下に出る一覧が同じ役割を果たす |
| 「年別」 | 上記の自動規則に含めて廃止 |

**挙動**: 棒タップでその日の記録が下に並ぶ。行タップでレコード詳細へ。

## 2. 画面遷移図

```
TabView（4 タブ）
├─ 計算: app/(tabs)/index.tsx（案 3a）
│    ├─(この内容で記録する)──> [sheet] RecordFormSheet（種別を引き継ぐ・SPEC-V2 §1.4）
│    └─(？)──────────────> [push/sheet] 使いかた（計算タブの節を開いた状態）
│
├─ 記録: app/(tabs)/records/index.tsx（案 8a）
│    ├─(行タップ)──────────> [push] app/(tabs)/records/[id].tsx（案 3d）
│    │      ├─(編集する)────> [sheet] RecordFormSheet（案 3c）
│    │      ├─(削除)────────> [alert] 削除確認
│    │      └─(？)──────────> 使いかた（記録の節）
│    ├─(＋ 記録)───────────> [sheet] RecordFormSheet（案 3c）
│    ├─(⌕)─────────────────> 検索バー（画面内・インライン）
│    ├─(⇅)─────────────────> [sheet] 並び替え＋種別フィルタ（先頭に「絞り込みをすべて解除」）
│    └─(月バー中央)─────────> [sheet] 表示する期間（全期間 / 各月）
│
├─ データ: app/(tabs)/data.tsx（案 7b）
│    ├─(棒タップ)──────────> 当日の一覧（画面内・グラフ下に展開）
│    ├─(行タップ)──────────> [push] レコード詳細（記録タブと同じ [id] ルート）
│    ├─(月バー中央)─────────> [sheet] 表示する期間
│    └─(？)─────────────────> 使いかた（データの節）
│
└─ 設定: app/(tabs)/settings/index.tsx（案 5b）
     ├─(使いかた)───────────> [push] app/(tabs)/settings/help.tsx → HelpScreen
     └─(書き出し CSV)───────> 共有シート（未実装・§5-7）

初回起動: 全画面シート 3 枚（計算する → 記録する → 見返す）。
          最後に「あとで見るには：設定 > 使いかた」と場所を明示。以降は自動表示しない。
          （実装優先度は最後・設計案 2e）
```

**シート = 下から出る一時的な面。月別詳細画面（`SaleRecordScreen`）は廃止し、一覧から詳細へ 1 タップ。**

## 5. 要確認

実装前に判断が必要な点。**§6 の矛盾とは別に、設計案が決めていない・現状のコードに存在しない事項**を挙げる。

1. **計算タブの種別セレクタの位置**
   設計案 `3a` は種別セレクタを**結果カードの下・入力カードの上**に置いている。
   SPEC-V2 §1.3 は「画面上部」。結果カードより下は「上部」と言えるか。
   なお仕入価格欄の直上なので、§1.5 の「切替で仕入価格欄が消えるのを目視できる」要件は満たす。
   → **提案: 設計案どおり（結果カードの下）で進める。** SPEC-V2 §1.3 の「画面上部」を
   「入力カードの直上」に読み替える。

2. **「N 日経過」の数え方**
   `8a` の出品中行と `3d` のメタ行に滞留日数が出るが、SPEC に定義がない。
   出品日当日を 0 日と数えるか 1 日と数えるか。売却済みの `3d` は「8/2 出品 → 8/9 販売（7日）」
   なので**差分 = 7 日、当日 0 日起算**と読める。出品中は「今日 − 出品日」。
   → **要確認: 0 日起算で確定してよいか。** 確定後 `src/logic/` に純粋関数として置く。

3. **「売れたら 約¥…（送料未定）」の判定条件**
   設計案の実装は `postage === 0` で「約」と「（送料未定）」を出す。
   しかし DB の `postage` は NOT NULL DEFAULT 0 で、**「未入力」と「送料 0 円（送料込み・手渡し）」を
   区別できない**。送料 0 円の出品を「送料未定」と表示してしまう。
   → **要確認: (a) 0 は常に「未定」扱いでよい / (b) `postage` を nullable にする /
   (c) この注記自体をやめる。** スキーマ変更を伴うので (a) を推す。

4. **売上の推移が見られなくなる件**（設計案 `6b` も懸念として明記）
   指標切替の廃止で、合計行の「売上」額は分かるが**売上が伸びているかは見られなくなる**。
   設計案は「必要になったら収支の棒の背後に薄い売上の棒を重ねる形（切替なし・1 グラフ）で戻せる」
   としている。
   → **要確認: 最初から薄い売上の棒を重ねるか、収支のみで出すか。**

5. **データタブの「期間を指定」の入口**
   設計案 `6b` の 62 日規則は「期間を指定して長い範囲を選んだとき」を前提にしているが、
   `7b` の UI には**月バーと期間シート（全期間 / 各月）しか描かれていない**。
   月単位でしか選べないなら、選べる期間は常に 1 か月（≤31 日）か全期間の 2 通りで、
   62 日規則が働く場面がない。
   → **要確認: (a) 期間シートに「期間を指定」を足す / (b) 62 日規則をやめて
   「月選択 = 日ごと / 全期間 = 月ごと」の 2 分岐にする。** 設計案 `7b` の注記
   （「全期間を選ぶと刻みが『月ごと』に変わり」）は (b) と整合する。

6. **設定「送料 = 前回の値を使う」の意味**
   `5b` に新規項目としてあるが、挙動が未定義。「前回保存した記録の送料を初期値にする」のか、
   固定値を選ぶ画面へ遷移するのか（右端が `▸` なので後者にも読める）。
   保存先も未定（`expo-sqlite/kv-store` に置くなら `src/settings/index.ts` の型に追加）。
   → **要確認: 挙動と選択肢。**

7. **設定「書き出し（CSV）」と「記録の件数」**
   CSV 書き出しは SPEC-V2 §6.2 でスコープ外とされ、未実装。`5b` では実装済みの体で描かれている。
   → **要確認: 本改訂に含めるか、行だけ置いて「準備中」にするか。**
   含める場合は SPEC-V2 §7-11 のとおり `kind` を 1 列として出す。
   「記録の件数」は `repository` に件数取得を 1 本足せば済む（軽微）。

8. **「クリア」の undo**
   設計案 `2e` は「クリアは入力が空でないときだけ有効。押した直後に『元に戻す』を数秒表示する」
   としている。スナックバー相当の部品が現状ない。
   → **要確認: 本改訂に含めるか、ステップ 3 の後に回すか。**

9. **各画面の「？」から開くヘルプの実装方式**
   「該当セクションを開いた状態で表示」するには `HelpScreen` にセクション ID を渡す必要がある。
   ルートパラメータ（`settings/help?section=records`）で渡すか、モーダルで開くか。
   記録タブ・データタブは設定タブとは別スタックなので、**タブをまたぐ push は素直に書けない**。
   → **提案: 「？」は `HelpScreen` をシート表示し、`section` を props で渡す。**
   設定タブの「使いかた」だけが push。

10. **`RecordListScreen` の検索バー（⌕）の出し方**
    `8a` はヘッダに ⌕ アイコンだけを描いており、押した後の状態が描かれていない。
    現状の `MonthlyRecordListScreen` は常時表示の `SearchBar`。上部を 3 段に抑えるのが `8a` の
    ねらいなので、常時表示に戻すと 4 段になる。
    → **提案: ⌕ タップでヘッダ行を検索フィールドに差し替える（段数を増やさない）。**

11. **`3c` の伝票カードに仕入価格行がない**
    設計案 `3c` のレシートは「販売価格 / − 送料 / − 手数料 / ＋ 梱包材・その他 / 純利益」で、
    仕入価格の行がない。サンプルが不用品なので非表示なだけとも読めるが、
    **仕入品のときどこに何と出るかが描かれていない**。
    → **提案: 「− 仕入価格」を「− 送料」の上に挿入する**（伝票の並びが控除の大きい順になる）。
    要確認。

12. **`3d` の下部 1 件サマリーの廃止**
    SPEC-V2 §1.3 は「レコード詳細の下部の 1 件サマリーは種別語を使う」としているが、
    `3d` にはその領域がなく、下端は編集・削除の操作列。レシートカードの結果行が同じ役割を果たす。
    → **要確認: §1.3 の当該行を「レシートカードの結果行」に読み替えて無効化してよいか。**

13. **`3d` の状態表示の重複**
    メタ行に「売れた」バッジがあり、その下に「売れた状態にする」トグルもある。
    同じ情報が 2 か所に出る。
    → **要確認: バッジを残してトグルは表示のみにするか、バッジを外すか。**

14. **月バーの「▶ 無効化」の基準**
    設計案は「最新月では ▶ を無効」としているが、最新月 = 今月か、データのある最新月か。
    データが今月にない場合の初期表示月も未定。
    → **提案: 初期表示は今月。▶ は今月で無効。** 要確認。

## 6. SPEC.md / SPEC-V2.md の決定と矛盾する箇所（実装しない）

**表示ラベルと種別の扱いは SPEC-V2 §5.3 / §5.4 の決定が優先する。**
以下は設計案の描画がその決定と食い違う箇所で、**設計案どおりには実装しない**。

### 6-1. 一覧行への種別の常時表示 — SPEC-V2 §5.4 と矛盾

- **設計案**: `8a` の行のメタ行が「不用品　8/9 販売」、`7b` の内訳行が「不用品　売上 ¥1,800」。
  全行に種別名が常時出る。
- **決定**: SPEC-V2 §5.4「**行や一覧に『不用品 / 仕入品』のバッジは置かない**。レコード詳細の
  商品情報カードにのみ『種別』行を 1 行置く。一覧で種別を知りたいときはフィルタで絞れる。」
  SPEC.md §3.2 にも「行には種別バッジを置かない」と反映済み。実装済み（`RecordRow.tsx`）。
- **判断**: **実装しない。** メタ行は日付（と出品中の見込み額・経過日数）のみとする。
  ただし §5.4 は「実機で見て判別が要ると感じたらこの項だけ再検討する（実装をブロックしない）」
  と留保しており、**設計案はその再検討を先取りした形**なので、再検討の議題としては有効。
  変更するなら SPEC-V2 §5.4 の改訂が先。
- **`3d` のメタ行「不用品 ・ 8/2 出品 → …」は矛盾しない**（レコード詳細なので §5.4 の対象外。
  ただし §1.3 は「商品情報カードの種別行」としており、置き場所だけが違う → §5-12 と同種の読み替え）。

### 6-2. 一覧行から金額ラベルが消える — SPEC-V2 §1.3 と矛盾

- **設計案**: `8a` の行は右上に金額だけ（`¥1,405`・色で正負）、メタ行右に「経費 ¥395」。
  「純利益 / 利益」の語が行から消える。
- **決定**: SPEC-V2 §1.3「行の金額ラベル: 不用品 = 純利益: ¥… / 仕入品 = 利益: ¥…」。
  実装済み（`RecordRow.tsx` が `profitLabel(record.kind)` を使用）。
- **判断**: **設計案どおりには実装しない。** 行は `純利益: ¥1,405` / `経費: ¥395` の形を維持する。
  §5.3 の「1 件を指すときは種別語」を行から外すと、種別語が詳細画面にしか残らず、
  §5.4（バッジなし）と合わせて**種別が一覧から完全に読めなくなる**ため、
  §6-1 と §6-2 を同時に採るのは特に避ける。

### 6-3. 出品中の合計「出品価格の合計」— SPEC-V2 §5.3 の語彙にない新語

- **設計案**: `8a` の出品中モードの合計行が「出品価格の合計」、行の主金額も「出品価格」。
- **決定**: SPEC-V2 §5.3 は `salesPrice` を「**販売価格**」（データタブの集計のみ「売上」）と定めている。
  「出品価格」は表になく、`labels.ts` にも定数がない。
- **判断**: **新語を増やさない。** 「販売価格の合計」または（集計なので）「売上」を使う。
  → **要確認: どちらにするか。** 出品中は「まだ売れていない額」なので「売上」は誤解を招く。
  **提案: 「販売価格の合計」。** 採用時は `labels.ts` に定数を足す。

### 6-4. 計算タブのセグメント名「利益を出す / 目標から逆算」— SPEC-V2 §1.3 / §5.3 と矛盾

- **設計案**: `3a` の結果カード先頭のセグメントが「利益を出す」「目標から逆算」（種別で変わらない）。
- **決定**: SPEC-V2 §1.3「セグメント名（結果側）: 純利益表示 / 利益表示」「（逆算側）:
  目標純利益逆算 / 目標利益逆算」。実装済み（`labels.ts` の `profitTabLabel` /
  `targetProfitTabLabel`）。
- **判断**: **実装しない。** 既存の `profitTabLabel` / `targetProfitTabLabel` をそのまま使う。
  設計案の名前は不用品でも「利益」と表示してしまい、§5.3 の「不用品 = 純利益」に反する。

### 6-5. 逆算入力のラベル「目標の利益」— SPEC-V2 §5.3 と軽微に矛盾

- **設計案**: `3a` は `目標の{純利益 or 利益}` で組み立てるため、仕入品では「目標の利益」。
- **決定**: SPEC-V2 §5.3「計算タブの逆算入力: 不用品『目標の純利益』/ 仕入品『**目標利益**』」
  （「の」なし）。実装済み（`labels.ts` の `targetProfitLabel`）。
- **判断**: **`targetProfitLabel(kind)` を使う。** 文字列を画面で組み立てない
  （§5.3「表示語は 1 箇所に集約する」）。

### 6-6. 記録フォームの種別セレクタの位置 — SPEC-V2 §1.3 / §1.5 と矛盾

- **設計案**: `3c` は種別セレクタを**日付カードの 3 行目**（販売日・出品日・種別）に置く。
- **決定**: SPEC-V2 §1.3「『商品情報』セクションの先頭に SegmentedControl」。
  §1.5「仕入品 → 不用品では、仕入価格を**その場で 0 にクリアし、欄が消える前に
  ユーザーが変化を目視できる**ようにする」。
- **判断**: **位置は設計案どおりにしない。** 種別セレクタが伝票カードの外（下）にあると、
  切替時に消える仕入価格行が**画面外またはスクロール上方**にあり得て、§1.5 の目視要件を満たせない。
  → **提案: 種別セレクタを伝票カードの見出し行（状態リンクの隣）か、
  商品名の直下に置く。** 要確認。

### 6-7. 計算タブヘッダの「設定」ボタン — 設計案の内部矛盾
