# 送料の専用資材 仕様 — SPEC-V6

出典: Claude Design プロジェクトの採用案 `45b`。
送料プリセットに「専用資材の代金」を持たせ、記録に入れるときに**使う／使わない**を選べるようにする。

**本書は SPEC.md / SPEC-V2〜V5 より後発**で、送料プリセットに関する記述が衝突する場合は本書が優先する。
プリセットそのものの規則（名前・色・頭文字・まとめ買い）は SPEC-V3 §1〜§4 のままで、本書はそこに列を 1 本足す。

**別書を立てた理由**: 送料プリセットが**金額を 2 つ持つ**のは、3 種のプリセットで初めての形
（SPEC-V3 §2.1 は「`value` 1 本・単位は type が決める」で書かれている）。
既存の書に混ぜると、その前提と本機能の例外が同じ節の中で戦う。

**触っていないもの**: 計算式（`src/logic/profit.ts`）・集計・絞り込み・CSV の**列**。
資材費は独立した経費ではなく**送料に含まれる**（§4）ので、計算にも列にも現れない。

---

## 0. 背景

一部の配送方法は**専用の箱・封筒を買わないと使えず**、その代金が送料とは別にかかる。
これまではプリセットが金額を 1 つしか持てなかったので、利用者が自分で足して入れるしかなかった。

**「梱包材」（`envelope_cost`）とは別のもの**:

| | 梱包材（SPEC-V3 §2.3） | 専用資材（本書） |
|---|---|---|
| 何か | 自分で選んで買う箱・封筒・緩衝材 | **その配送方法でしか使えない**指定の資材 |
| 選び方 | 梱包材プリセットから複数選ぶ（§4.5） | 送料プリセットに**くっついてくる** |
| 記録での行き先 | `envelope_cost` | **`postage`（送料に含める）** |

## 1. データ

### 1.1 プリセット（`presets.material_cost`）

```ts
materialCost: real('material_cost').notNull().default(0)  // 円。送料以外は常に 0
```

- **送料プリセットだけが使う。** 販売サイト（率）・梱包材には概念がない。
- `value`（送料そのもの）とは**別の列**にする。合算した 1 つの値で持つと、
  §3 の「今回は資材を使わない」をあとから引き算できない。
- **まとめ買いの 2 列（`pack_quantity` / `pack_price`）は、送料プリセットではこの列の材料になる**
  （梱包材では `value` の材料。SPEC-V3 §2.6）。列を増やさないのは、送料の `value` が
  「1 回いくら」でまとめ買いの概念を持たないため。振り分けは `logic/preset.packBuyTarget()`。

### 1.2 記録（`sale_records` の 2 列）

```ts
shippingMaterialCost: real('shipping_material_cost').notNull().default(0)
excludesShippingMaterial: integer('excludes_shipping_material', { mode: 'boolean' })
  .notNull().default(false)
```

- **`postage` はこれまでどおり「支払う送料の総額」**で、資材費はそこに含まれる
  （「送料のみ」を選んだ記録では含まれない）。
- 上の 2 列は**金額の計算に一切入らない**。`profit.ts` も CSV も `postage` しか見ない。
  入っているのは「選んだときの資材費がいくらだったか」と「どちら側を選んだか」の**控え**だけ。
- 控えを記録が持つのは、**記録がプリセットを id で参照しないから**（SPEC-V3 §1.5）──
  プリセットを見に行っても、選んだ当時の資材費は分からない（あとから直っているかもしれない）。

### 1.3 マイグレーション（0006）

`ALTER TABLE ... ADD COLUMN` の 3 本だけ。**バックフィルをしない**（SPEC-V5 §2.1 と同じ作法）。

- 既存のプリセットは資材費 0 円になり、**送料（`value`）は 1 円も書き換えない**。
- 既存の記録は控えが 0 / false になり、**金額の列は 1 つも動かない**。

## 2. プリセットの編集画面（SPEC-V3 §3.3 の拡張）

送料のときだけ、名前・金額のカードの下に **2 枚**が増える。

```
[ 名前 ]  [ 金額 450 ]

専用資材   ( 1個ずつ | まとめ買い )
専用資材の代金                    70

金額                            450 円
専用資材                          70 円
────────────────────────────────
合計                            520 円
記録でこのプリセットを選ぶと、この合計が送料に入ります。
```

- **資材費は 0 円を許容する。** 多くの配送方法では資材費がかからないので、
  空欄のまま保存できる（空欄 = 0 円）。0 円のときは欄も**空欄から始める** ──
  金額欄と違って「0」を置くと、打ち始めたときに `070` になる。
- 桁数は**小数第 1 位まで**（送料そのものは整数のみ）。まとめ買いの単価（15.5 円など）が
  そのまま入り得るため、梱包材と同じ扱いにする。
- **まとめ買い**は梱包材と同じ 3 行（入数 → 購入価格 → 1 個あたり）で、部品も同じ
  （`components/PackBuyFields.tsx`）。単価が入る先だけが違う（§1.1）。
- 内訳カードを出すのは、**合計だけでは「何と何を足した額なのか」が画面から読めない**ため。

一覧（設定タブ）と編集画面のプレビューでは、名前の下に「＋専用資材 70円（合計 520円）」を
小さく足す ── 右端の金額（送料）だけを見て選ぶと、記録に入る額と食い違うため。
**選択シート（§3）はこの副題を出さない**（セグメントが同じことを言うので）。

## 3. 選択シート（採用案 `45b`）

資材費のあるプリセットの行**だけ**、名前の下にセグメント 2 択を常時出す。

```
 小   専用箱（小）                    450円
      [ 送料のみ | ＋資材 100円 ]
```

- **どちらを押しても、その場でプリセットの選択と資材の有無が同時に決まる**（1 タップ）。
- **既定は「＋資材」側。行そのものを押したときもこちら。** 資材費を登録してあるプリセットは、
  その資材を使う前提で登録されているため。
- 選択中の行は**右端の金額が選んだ側の額**になり（送料のみ = 450円 / ＋資材 = 550円）、
  **✓ と薄い青の下地**が付く。選ばれていない行はどちらのセグメントも持ち上げない
  （`SegmentedControl` の `selectedIndex: null`。採用案 `22b` と同じ語法）。
- **資材費 0 円のプリセットにはセグメントを出さない。** 行の形は従来のまま。
- 寸法は 45b の指定どおり **高さ 34pt・幅 212pt**、行は **96pt** に伸びる。
  34pt は親指には低いので、当たり判定だけ上下 6pt ずつ広げて 46pt を確保する
  （高さそのものを 44pt にすると、1 枚のシートに並ぶ行数が減る）。

### 3.1 どちら側が効いているかの復元

**欄に入っている額から引く**（`logic/shippingMaterial.shippingMaterialChoiceOf`）。
保存済みの `postage` は選んだ側の額そのものなので、記録を開き直したときの復元もこれで足りる。
手で打ち替えた額はどちらとも一致せず、その行は選ばれていない扱いになる（✓ も付かない）── 
プリセットの札（SPEC-V3 §4.1）が「一致した行にだけ付く」のと同じ規則。

### 3.2 記録フォームのトグルは廃止（本改訂）

初版（本書の旧 §3）は、シートで選んだあと**記録フォーム側のトグル**
「専用資材を使わない」で切り替える形だった。45b でこれを**廃止**する ──
選ぶ時点で決められるなら、「選んでから別の場所でもう一度決める」のは余計な 1 手で、
しかも金額が動く操作が 2 か所に分かれる。

**列（§1.2）はそのまま残す。** 保存済みの記録の値は失われず、書き手がトグルからセグメントに
変わっただけ。

### 3.3 計算タブ

送料の行は記録フォームと**同じ部品**（`NumericField presetType="shipping"`）なので、
45b はそのまま計算タブにも効く。計算タブには控えの置き場（`CalcFormValues`）が無いので、
入るのは金額だけ ── 記録に持ち越されるのは「この内容で記録する」で開いた記録フォームの側の話になる。

## 4. CSV（SPEC-V3 §5 の追補）

**資材費は送料の列に含まれた額で出る**（データ保存用 18 列・確定申告用 11 列とも）。
`postage` をそのまま出すので、列の定義も丸めの規則（§5.4）も変わらない。
**梱包材の列には入れない** ── 送料の一部として払うものだから。

プレビュー画面（案 `40c`）にだけ「送料には専用資材の代金を含みます」の 1 行を出す。
**ヘッダ行には入れない** ── 列名は表計算ソフトがそのまま項目名にするので、注記が混ざると邪魔になる。

## 5. 開発用テストデータ

`src/dev/devSeed.ts` の初期プリセットのうち **2 件**（「専用箱（小）」「専用箱（中）」）が
資材費を持ち、`src/dev/testData.ts` が「送料のみ」を選んだ記録を **3 件**作る。
資材費のあるプリセットが 1 つも無い環境では、その 3 件も普通の記録になる。
