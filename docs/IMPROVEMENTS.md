# 移植後にやりたい改善

## 利用モードの切替（最重要）
このアプリには2つの利用者層がある：
- 不用品を売る人：仕入価格の概念がない。関心は「手取りがいくらか」
- 転売する人：仕入価格が明確。関心は「利益がいくらか」

計算式は両者で完全に同一（不用品は仕入=0）。データ構造も共通。
差分は表示のみなので、設定でモードを切り替える方式とする。

| 項目 | 不用品モード | 転売モード |
|---|---|---|
| 仕入価格欄 | 非表示（0固定、任意で開ける） | 常に表示 |
| 結果ラベル | 手取り | 純利益 |
| 逆算ラベル | いくら残したい | 目標利益 |
| 出品中タブ | 売却待ち | 在庫 |

ストア掲載時は不用品側を主軸に訴求する（対象人数が多く、競合が薄いため）。

## 差別化候補（優先度順）
- 手数料率のプリセット。サービス名はアプリ側に持たず、ユーザーが率と名前を
  自由登録する方式にする（法的リスク回避 + 料率改定に自動追従）。platform列が前提
- 出品中の滞留日数表示と、長い順ソート
- 値下げの下限提示。「○%下げる」ではなく「赤字にならない最低価格」と
  価格帯ごとの手取り一覧を示し、判断は本人に委ねる。逆算ロジックを流用
- 赤字アラート。警告のみで保存は可能にする（あえて赤字で売る場面があるため）
- CSVエクスポート（確定申告向け）
- 利益推移のグラフ強化
- 月次レポートのローカル通知（Expo Notifications、サーバー不要）
- 送料早見表。「YYYY年M月時点」を明記し、自由入力を常に可能にして
  表が古くなっても機能が壊れないようにする

### 梱包材プリセット
背景：梱包材の費用は「封筒100枚入りのうち1枚」「プチプチ＋ダンボール併用」のように
1件あたりの金額が即座に出せず、結果として入力されず空欄のままになっている。
一方で利用者は梱包材の選択自体にはこだわっている（破損による評価低下を避けるため）ので、
選ぶ行為はすでに日常的に行っている。

仕様案：
- 設定画面で梱包材を登録できる。項目は名前と1個あたりの金額
- 登録時に「入数」と「購入価格」から1個あたりの金額を自動計算できる補助を用意する
  （例：100枚800円 → 8円）
- レコード入力時は登録済みの梱包材を複数選択でき、合計が梱包材費の欄に自動入力される
- 手動での上書きも可能（従来どおり自由入力を維持）

同種で複数メーカーの梱包材を使い分ける場合の識別方法：
- 第1案（採用）：名前とメモ欄で区別する。名前は自由入力なので
  「プチプチ（幅広）」「封筒（茶・大）」のように利用者が分かる形で登録できる。
  メモにはメーカー名や購入先を記載できる
- 第2案（将来）：写真の添付。名前だけで思い出せないほど種類が増えた場合に検討する。
  ただし登録のハードルが上がるため、初期実装では見送る
- 第3案（不採用）：購入先URLの保存。商品ページが消えたり変わったりするため信頼性が低い。
  必要ならメモに記載すれば足りる

登録のハードルを下げることを優先する（現状、梱包材費は入力されず空欄のままになっているため）。

期待効果：
- 入力されないままだった梱包材費が実データとして蓄積される
- 「今月の梱包材費」が集計できるようになる

## UI改善

### 計算タブ
- 純利益を画面最上部に大きく表示する。スクロールして画面外に出たら、
  上部に小さく固定表示される形にする（iOSの一般的な挙動に合わせる）
- 純利益をタップすると内訳（売上・仕入・送料・梱包材・手数料）が開く
- 入力欄は「販売価格・仕入価格・送料」を常時表示とし、
  梱包材・その他は畳んでおく（毎回入力されていないため）
- 結果表示を上部に置く理由：キーボードで画面下半分が埋まるため、
  下部固定にすると入力中に見えなくなる

### 出品中・実績タブの階層構造
現状：全体一覧 → 月ごと → その月の詳細リスト → レコード詳細（3階層）
問題：1件の詳細に到達するまでのタップ数が多い。また日単位の絞り込みは
実際にはほとんど使われない想定

改善案：月の選択を階層ではなくフィルタにする
- 画面上部に「◀ 2026年8月 ▶」の月切り替えバーを置く
- その下に月次サマリー（収支・経費）
- その下にその月の全レコードをフラットに並べる
- 月表示をタップすると年月ピッカーが開き、「全期間」も選べる
- これにより一覧からレコード詳細まで1タップになる（現状は2タップ）
- 月の移動も矢印1つで済む（現状は戻って選び直しで2アクション）

補足：データタブの期間指定と同じ「フィルタ」の考え方に統一されるため、
アプリ全体の操作感が揃う

### 種別フィルタの発見しにくさ
現状：Step 4 で種別フィルタをソートメニュー（OptionSheet）内に統合したが、
8択のソートの下に配置されたため、スクロールしないと見えない状態になっている
問題：開発者自身が実機で気づかなかったため、実利用者はまず発見できないと考えられる

対処案：
- ソートより上に種別を配置する（使用頻度は種別フィルタの方が高いと想定）
- 一覧上部にセグメントコントロールとして常設する
  （ただし縦幅を消費するため、月切り替えバーの導入と併せて設計する。
  上記「出品中・実績タブの階層構造」と同じ画面上部を取り合うため）

補足：SPEC-V2 §7-10 の「縦幅を節約するためソートメニューに統合」という決定は、
結果として発見可能性を犠牲にしていた。UI全体の見直し時に再検討する

## 方針メモ
- サービス名（メルカリ等）はアプリ内・アプリ名・説明文のいずれにも含めない。
  誤認リスクと、用途を狭める懸念があるため
- 広告は計算・入力画面には絶対に置かない。一覧/グラフ画面のみ
- 買い切り課金は見送り（App Store Connectの有料アプリ契約手続きが負担）。
  ただし広告収入でもAdMobの税務情報・支払い先登録は必要な点に留意
