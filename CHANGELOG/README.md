# CHANGELOG 記法ルール

App Store / Google Play に出したリリースノートを、バージョンごとにそのまま残す場所です。

## バージョン方針

- iOS と Android は**同一のバージョン番号**を使う（マーケティングバージョン／`versionName`）。
  - iOS: Xcode の `MARKETING_VERSION`
  - Android: `android/app/build.gradle` の `versionName`
- ビルド番号（iOS の `CURRENT_PROJECT_VERSION` / Android の `versionCode`）は両 OS で独立してカウントし、統一しない。
- Android は 1.0 を経ずに **1.1 から公開**する（iOS 側の初回公開が 1.0 のため、番号を合わせてスタートする）。

## ファイル名

`CHANGELOG/<バージョン>.md`（例: `1.0.md`, `1.0.1.md`, `1.1.md`）。
パッチ版（x.y.z）も同じ階層にフラットに置く。

## 注意

github にあげるため個人情報や機密情報は記入しないこと。

## 各ファイルの記法

```markdown
# <バージョン>

## リリース状況

- iOS: <提出日 / 公開日 / 未提出 などの状態>
- Android: <同上>

## 新機能

- ...

## 改善

- ...

## 修正

- ...

## その他

- ストア掲載情報・署名・広告設定など、アプリの挙動に直結しない運用上の変更
```

- 見出しは実際に変更があった分類だけを書く（該当なしの見出しは省略してよい）。
- 各項目には、根拠となる git のコミットハッシュ（短縮形）を末尾に付記する
  （例: `- ポリゴン編集の保存不具合を修正 (53c80d5)`）。
  ストア側のみの変更（マーケティング URL、apps-ads.txt、ストア掲載名など）で
  このリポジトリにコミットが存在しない場合は、その旨を明記する。
- 日付は `YYYY-MM-DD` 形式。判明している範囲で「提出日」「公開日」を分けて書く。
  提出したがまだ審査中/公開待ちの場合は「提出日: ... / 公開日: 未定」のように書く。

## 分類の目安

| 分類   | 内容                                                                            |
| ------ | ------------------------------------------------------------------------------- |
| 新機能 | ユーザーから見て新しくできるようになったこと                                    |
| 改善   | 既存機能の使い勝手・表示・パフォーマンスの変更                                  |
| 修正   | 不具合の修正                                                                    |
| その他 | ストア掲載情報、署名、広告 ID、社内向けツールなど、アプリの動作に直結しない変更 |
